# 02. 통합 체인 실행

> 컨테이너에서 스테이지를 도출하고, 무엇을 실행하고 무엇을 건너뛰고, 머신이 무엇을
> 제공하는지. 명령은 `/sboot-rehost:start`.

---

## 1. 스테이지 지도 도출 (`stage_map.py`)

벤더 부트로더 이미지는 여러 스테이지가 이어 붙은 컨테이너다. 평문·암호화·부재가 섞여 있다.

| # | 단계 | 방법 |
|---|---|---|
| 1 | 구간 분류 | 엔트로피 격자로 평문 / 암호화 / 제로 패딩 구분 |
| 2 | 스테이지 경계 | 아키텍처별 리셋 스텁 시그니처 탐색 |
| 3 | 구간 식별 | 문자열 문맥으로 정체 판별 |
| 4 | 적재 주소 | basefind 후 **리터럴 앵커로 교차 검증** |

- **4단계 교차 검증은 생략 불가.** 포인터 포함률만으로 고른 후보는 실측에서 틀렸다
  (약 `0xBE000000` 차이). BSS 포인터를 파일 오프셋으로 환산했을 때 **제로 패딩 시작
  지점에 정확히 착지**해야 확정값이다.
- 앵커 없는 후보는 `confidence: candidate`. **확정값으로 쓰지 않는다.**

### 리셋 스텁 시그니처 (AArch64)

```
b    .+4
adr  x0, <벡터 테이블>
mrs  x1, currentel
cmp  x1, #8  → msr vbar_el2
cmp  x1, #4  → msr vbar_el1
     그 외   → msr vbar_el3 ; scr_el3 |= 0xf
```

- `mrs xN, currentel` 단독은 조회 함수다. **벡터 베이스 기록이 근처에 있어야** 스테이지 경계.
- AArch32 는 `CurrentEL` 이 없다. 종료코드 3 → `BLOCKED_ARCH`.
  **"스테이지가 없다"가 아니라 "도구가 없다"** 이며, 이 구분을 흐리면 도구 결손이
  펌웨어 판정으로 둔갑한다.

### 산출

`stage_map.json`: 스테이지마다 `{name, file_range, state, load_base, entry_pc, evidence}`.
목표 단계가 여기서 만들어지므로 **배치 못 한 스테이지는 겨냥할 수 없다.**

## 2. 건너뛰기

실행 불가한 스테이지는 이전 스테이지의 진입을 **다음 실행 가능 스테이지로 재지정**한다.

정당성 조건: 이후 스테이지가 건너뛴 스테이지의 메모리를 읽지 않아야 한다.
확인 방법은 진입 코드가 **쓰기 전에 읽는 것**을 열거하는 것이다.

| 읽는 대상 | 판정 |
|---|---|
| 하드웨어 레지스터 | 문제없음. 머신이 어차피 모델링한다 |
| 이전 스테이지가 쓴 메모리 | 값 공급이 필요하며, 공급 자체가 우회다 |
| 분류 불가 | **미확정으로 기록.** 레지스터라고 가정하지 않는다 |

**대신할 값을 지어내지 않는다.** 이후 단계가 그런 값을 요구하면 그것은 보고할 사실이지
채워 넣을 대상이 아니다.

## 3. 머신이 제공하는 것

| 항목 | 내용 |
|---|---|
| 리셋 PC | 첫 스테이지 진입점 (도출값) |
| 진입 EL | 스테이지의 진입 스텁이 쓰는 `vbar_el*` 가 정한다 |
| 스테이지 배치 | 컨테이너를 한 번 읽어 스테이지별 적재 주소로 복사 |
| 이전 단계 핸드오프 | 첫 스테이지가 호출하는 함수 포인터 슬롯 |
| 메모리 골격 | DRAM · SRAM · 주변장치 창 |
| UART | 송신 1지점, 수신은 chardev 콜백만 |
| SMC shim | 펌웨어가 실제 발행하는 function id 별 응답 |
| 부팅 매체 | 합성 GPT 디스크 → [03-boot-medium.md](03-boot-medium.md) |

### 함정 셋

- **진입 PC ≠ 적재 주소.** 파일 오프셋 0 은 컨테이너 헤더다. 거기로 진입하면 헤더
  바이트를 명령으로 실행한다. 도출 실패 시 적재 주소로 대체하지 말고 빌드 실패로 보고.
- **진입 EL 에 기본값을 두지 않는다.** `has_el3=false` 를 기본으로 두면 `vbar_el3` 를
  쓰는 스테이지가 조용히 깨진다. 반대도 같다. 답은 `stage_map.json` 에 있다.
- **머신은 입력을 만들지 않는다.** 수신 버퍼를 채우는 것은 chardev 콜백뿐이며,
  입력은 `uart_harness.py` 가 QEMU 외부에서 넣는다.

### 핸드오프 슬롯

첫 스테이지에는 이전 단계가 없으므로 BootROM 이 남겼을 것을 모델링한다.

- 상수 주소를 적재한 뒤 간접 호출하는 지점을 찾는다
- 각 슬롯의 계약은 **호출부의 인자 구성에서** 도출한다. 위치로 추정하지 않는다
- **호출되는 슬롯만** 모델링한다. BootROM 전체 흉내는 필요하지도 가능하지도 않다
- 여기서 채운 슬롯은 전부 우회이며 기록 대상이다. BootROM 의 산출물을 모델링한 것이지
  BootROM 을 실행한 것이 아니다

## 4. 인터랙티브 표면

UART 셸 또는 fastboot/USB 이며 **도출값**이다.

- **UART**: 드라이버에 수신 경로(RBR 읽기, rx 폴링)가 있는가. 출력 전용이면 셸이 없다
- **USB**: 디스패처가 명령 테이블을 참조하는가
- 테이블이 있어도 순회하는 디스패처가 없으면 도달 불가
- 어느 표면에도 입력 경로가 없으면 `BLOCKED_NO_INPUT_PATH`

### 입력 게이트

- 부팅 중 콘솔을 잠깐 폴링해 **특정 바이트 연속 입력**(대개 CR `0x0d` N회)이 오면 셸로 간다
- 게이트는 보통 일회성이라 그 창이 열린 동안 도착해야 한다
- 연타 수와 게이트 주소는 도출값이며 `input_plan.json` 에 기록
- 도출 실패 시 하네스가 기본값을 쓰고 **기본값이었다고 기록**한다

## 5. 서명 검증

**이미지는 벤더가 서명했고 검증 코드도 벤더 것이므로, 원래 통과해야 정상이다.**
실패하면 대개 펌웨어가 아니라 우리가 준 입력이 잘못됐다.

조사 순서. 검증 코드는 가장 마지막에 의심한다.

1. 매체에 그 파티션이 그 이름으로 있는가
2. 읽어온 바이트가 맞는가 (블록 크기·GPT 오프셋 오류는 그럴듯한 쓰레기를 만든다)
3. 롤백 인덱스 읽기가 응답하는가
4. 키 대조 대상이 있는가
5. 그다음에야 연산 경로

**검증을 패치로 무력화하지 않는다.** 검증을 끄고 커널에 도달한 실행은 커널을 직접 적재한
것과 같은 것을 보여줄 뿐이다. 정직하게 통과시킬 수 없으면 보고하고 정지한다.

---

## 6. 커널 진입

- 부트로더가 매체에서 boot image 를 읽고, 검증하고, DTB 를 조립해 점프한다
- 머신은 그 코드가 접근하는 것만 제공한다
- 램디스크 크기가 0 이면 **system-as-root**. initramfs 가 없으므로 **스토리지 모델이
  동작하기 전에는 유저스페이스가 존재하지 않는다**
- `Starting kernel...` 출력(`kernel_entry`)과 커널 배너 출력(`kernel_alive`)은 다르다.
  앞의 것만으로 도달을 세지 않는다

## 7. 정지 조건

| 코드 | 뜻 |
|---|---|
| `BLOCKED_VERSION` | 로드된 플러그인이 최신이 아님 |
| `BLOCKED_ENV` | 실행 환경 미비 |
| `BLOCKED_ARCH` | 그 아키텍처의 진입 스텁 시그니처 미정의 |
| `BLOCKED_CARVE` | 컨테이너가 부분 추출 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로 없음 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산 없음 |
| `BLOCKED_TEE` | 시큐어 월드. 설계상 범위 밖 |
| `EXHAUSTED` | 시도 소진 |

정지 시 `RESUME.md` 자동 생성. **정지는 인계다.**
