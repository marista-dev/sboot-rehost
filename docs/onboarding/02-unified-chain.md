# 02. 통합 체인 실행

> **읽고 나면**: 컨테이너 하나에서 스테이지를 어떻게 도출하고, 무엇을 실행하고 무엇을
> 건너뛰는지, 머신이 무엇을 제공해야 하는지 알 수 있다.
>
> 명령: `/sboot-rehost:start`

---

## 1. 스테이지 지도 도출

벤더 부트로더 이미지는 여러 스테이지가 이어 붙은 컨테이너다. 일부는 평문으로 실행 가능하고,
일부는 실리콘에 있는 키로 암호화되어 있으며, 일부는 패키지에 아예 없다.

**어느 것이 어느 것인지, 각각 어디에 적재되고 어디서 시작하는지**를 도출로 확정한다.
`scripts/stage_map.py` 가 네 단계로 수행한다.

| # | 단계 | 방법 |
|---|---|---|
| 1 | 구간 분류 | 엔트로피 격자로 평문 / 암호화 / 제로 패딩 구분 |
| 2 | 스테이지 경계 | 아키텍처별 리셋 스텁 시그니처 탐색 |
| 3 | 구간 식별 | 문자열 문맥으로 각 구간의 정체 판별 |
| 4 | 적재 주소 | basefind 후 **리터럴 앵커로 교차 검증** |

### 4단계의 교차 검증은 생략할 수 없다

포인터 포함률만으로 고른 후보는 실제 펌웨어에서 틀렸다(약 0xBE000000 차이). 이미지 내부의
BSS 포인터를 파일 오프셋으로 환산했을 때 **파일의 제로 패딩이 시작되는 지점에 정확히
착지**해야 비로소 확정값이다.

앵커가 없는 후보는 `confidence: candidate` 로 표기되며, **확정값으로 쓰지 않는다.**
후보 위에 머신을 만들면 재생성 비용을 치른다.

### 리셋 스텁 시그니처 (AArch64)

```
b    .+4                  짧은 분기
adr  x0, <벡터 테이블>
mrs  x1, currentel
cmp  x1, #8  → EL2 분기 → msr vbar_el2
cmp  x1, #4  → EL1 분기 → msr vbar_el1
             그 외      → msr vbar_el3 ; scr_el3 |= 0xf
```

`mrs xN, currentel` 단독은 조회 함수이지 스테이지 경계가 아니다. **벡터 베이스 기록이 근처에
있어야** 스테이지 시작으로 인정한다.

AArch32 는 `CurrentEL` 이 없어 이 시그니처가 적용되지 않는다. `stage_map.py` 는 종료코드 3 을
반환하고 파이프라인은 `BLOCKED_ARCH` 로 정지한다. **"스테이지가 없다"가 아니라 "도구가 아직
없다"** 이며, 이 구분을 흐리면 도구의 결손이 펌웨어에 대한 판정으로 둔갑한다.

### 산출물

`stage_map.json` — 스테이지마다
`{name, file_range, state: exec|encrypted, load_base, entry_pc, evidence}`

목표 단계가 여기서 만들어지므로, **배치하지 못한 스테이지는 겨냥할 수 없는 스테이지**다.

## 2. 건너뛰기

실행 불가한 스테이지는 이전 스테이지의 진입을 **다음 실행 가능한 스테이지로 재지정**한다.

### 정당성 조건

이후 스테이지가 건너뛴 스테이지가 쓴 메모리를 읽지 않아야 한다. 확인 방법은 진입 코드가
**무엇을 쓰기 전에 읽는가**를 열거하고 분류하는 것이다.

| 읽는 대상 | 판정 |
|---|---|
| 하드웨어 레지스터 (리셋 상태, 부트 모드 등) | 문제없음. 머신이 어차피 모델링한다 |
| 이전 스테이지가 쓴 메모리 | 그 값을 공급해야 하며, 공급 자체가 우회다 |
| 분류 불가 | **미확정으로 기록.** 레지스터라고 가정하지 않는다 |

### 지어내지 않는다

건너뛴 스테이지를 대신할 값을 만들어 넣지 않는다. 이후 단계가 그런 값을 필요로 한다면
**그것은 보고할 사실이지 채워 넣을 대상이 아니다.**

## 3. 머신이 제공하는 것

| 항목 | 내용 |
|---|---|
| 리셋 PC | 첫 스테이지의 진입점 (도출값). 적재 주소가 아니다 |
| 진입 EL | 스테이지의 진입 스텁이 쓰는 `vbar_el*` 가 정한다 |
| 스테이지 배치 | 컨테이너를 한 번 읽어 스테이지별 적재 주소로 복사 |
| 이전 단계 핸드오프 | 첫 스테이지가 호출하는 함수 포인터 슬롯 |
| 메모리 골격 | DRAM · SRAM · 주변장치 창 |
| UART | 송신 1개 지점, 수신은 chardev 콜백만 |
| SMC shim | 펌웨어가 실제로 발행하는 function id 별 응답 |
| 부팅 매체 | 합성한 GPT 디스크 → [03-boot-medium.md](03-boot-medium.md) |

### 진입 PC 는 적재 주소가 아니다

파일 오프셋 0 은 컨테이너 헤더다. 거기로 진입하면 헤더 바이트를 명령으로 실행해 첫 워드에서
트랩한다. 진입점을 도출하지 못했으면 **적재 주소로 대체하지 말고 빌드 실패로 보고**한다.

### 진입 EL 에 기본값을 두지 않는다

`has_el3=false` 를 기본으로 두면, `vbar_el3` 를 쓰는 첫 스테이지가 조용히 깨진다.
반대 기본값도 마찬가지다. **스테이지 자신이 쓰는 벡터 레지스터가 답**이며 `stage_map.json`
에 기록되어 있다.

### 이전 단계 핸드오프

첫 스테이지에는 이전 단계가 없으므로, BootROM 이 남겼을 것을 모델링해야 한다.
슬롯은 도출한다: 상수 주소를 적재한 뒤 간접 호출하는 지점을 찾고, **각 슬롯의 계약을 호출부의
인자 구성에서** 도출한다. 슬롯의 위치가 시사하는 바로 추정하지 않는다.

호출되는 슬롯만 모델링한다. 개수는 작고 도출 가능하며, BootROM 전체를 흉내 내는 것은
필요하지도 가능하지도 않다. **여기서 채운 슬롯은 전부 우회이며 기록 대상이다** — BootROM 의
산출물을 모델링한 것이지 BootROM 을 실행한 것이 아니다.

### 머신은 입력을 만들지 않는다

수신 버퍼를 채우는 것은 chardev 콜백뿐이다. 자체 입력 주입은 검증 항목에서 불통과 처리된다.
입력은 `uart_harness.py` 가 QEMU 외부에서 넣는다.

## 4. 인터랙티브 표면

부트로더의 표면은 UART 셸 또는 fastboot/USB 이며 **도출값**이다.

- **UART**: 드라이버에 수신 경로(RBR 읽기, rx 폴링)가 있는가? 출력 전용 UART 는 셸을 실을 수 없다
- **USB**: 어떤 디스패처가 있고, 그중 명령 테이블을 참조하는 것이 있는가?

명령 테이블이 바이너리에 존재해도 이를 순회하는 디스패처가 없으면 도달 불가다.
어느 표면에도 입력 경로가 없으면 `BLOCKED_NO_INPUT_PATH` 로 정지한다.

### 입력 게이트

부트로더는 부팅 중 콘솔을 잠깐 폴링해 **특정 바이트 연속 입력**(대개 CR 0x0d N회)이 있으면
셸로, 없으면 자동 부팅으로 간다. 게이트는 보통 일회성이라 그 창이 열린 동안 패턴이 도착해야
한다.

연타 수와 게이트 주소는 도출값이며 `input_plan.json` 에 기록한다. 도출하지 못하면 하네스가
문서화된 기본값을 쓰고 **기본값이었다고 기록**한다.

## 5. 서명 검증

부트로더는 커널을 적재하기 전 자체 검증(AVB 등)을 수행한다.

**이미지는 벤더가 실제로 서명한 것이고 검증 코드도 벤더의 것이므로, 검증은 원래 통과해야
정상이다.** 실패한다면 대개 펌웨어가 아니라 우리가 준 입력이 잘못된 것이다.

조사 순서 — 검증 코드는 가장 마지막에 의심한다.

1. 매체에 해당 파티션이 그 이름으로 있는가 (이름은 부트로더 문자열에서 도출)
2. 읽어온 바이트가 맞는가 (블록 크기·GPT 오프셋 오류는 그럴듯한 쓰레기를 만든다)
3. 롤백 인덱스 읽기가 응답하는가
4. 키 대조 대상이 있는가
5. 그다음에야 연산 경로. 해시·RSA 가 부트로더 내부 소프트웨어 구현이면 TCG 가 그대로 실행한다

### 검증을 패치로 무력화하지 않는다

검증을 끄고 커널에 도달한 실행은 **커널을 직접 적재한 것과 같은 것을 보여줄 뿐이다.**
정직하게 통과시킬 수 없다면 그것을 보고하고 정지한다.

---

## 6. 커널 진입

부트로더가 매체에서 boot image 를 읽고, 검증하고, DTB 를 조립해 커널로 점프한다.
이 구간은 부트로더 자신의 코드가 수행하며, 머신은 그 코드가 접근하는 것만 제공한다.

boot image 의 램디스크 크기가 0 이면 **system-as-root** 다. initramfs 가 없으므로
**스토리지 모델이 동작하기 전에는 유저스페이스가 존재하지 않는다.**

## 7. 정지 조건

| 코드 | 뜻 |
|---|---|
| `BLOCKED_VERSION` | 세션이 로드한 플러그인이 최신이 아님 |
| `BLOCKED_ENV` | 실행 환경 미비 |
| `BLOCKED_ARCH` | 해당 아키텍처의 진입 스텁 시그니처 미정의 |
| `BLOCKED_CARVE` | 컨테이너가 부분 추출 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로 없음 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산 없음 |
| `BLOCKED_TEE` | 시큐어월드 — 설계상 범위 밖 |
| `EXHAUSTED` | 시도 소진 |

정지 시 `RESUME.md` 가 자동 생성된다. 정지는 중단이 아니라 인계다.
