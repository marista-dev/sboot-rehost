# 01. 리호스팅 개요

> **읽고 나면**: 이 저장소가 무엇을 하는지, 부팅 체인의 어디를 어디까지 실행하는지,
> 왜 그것이 커널 이미지만 실행하는 것과 다른지 알 수 있다.

---

## 1. 리호스팅이란

기기 없이, 기기의 펌웨어를 **원본 바이너리 그대로** 다른 환경에서 실행시키는 것이다.
재구현이 아니다. 펌웨어 코드는 손대지 않고, 그 코드가 접근하는 **환경**을 만든다.

| | 에뮬레이션 | 리호스팅 |
|---|---|---|
| 대상 | 하드웨어 전체 | 펌웨어가 실제로 접근하는 부분만 |
| 목표 | 정확한 재현 | 코드가 계속 실행되게 하는 것 |
| 미모델 주변장치 | 구현 필요 | 접근 시점에 관찰 후 그 창만 모델링 |

## 2. 휴대폰의 부팅 순서

각 단계는 다음 단계를 검증하고 넘겨준다. 이것이 verified boot chain 이다.

| # | 단계 | 하는 일 |
|---|---|---|
| ① | BootROM | SoC 내장 ROM. 변경 불가. 다음 단계를 적재·검증 |
| ② | 1차 부트로더 | DRAM 초기화, 보안 환경 설정 |
| ③ | 부트로더 | S-Boot(삼성) / LK(미디어텍) / aboot(퀄컴). UART 셸, fastboot, 파티션 적재, 커널 적재 |
| ④ | EL3 모니터 | 보안 모니터(TF-A). PSCI·SMC 서비스 |
| ⑤ | EL2 하이퍼바이저 | 최근에는 커널에 내장 |
| ⑥ | 커널 | Linux 시작 |
| ⑦ | init 1단계 | rootfs 탐색·마운트 |
| ⑧ | init 2단계 | 안드로이드 서비스 기동 |
| ⑨ | Android | 홈 화면 |

### ARM Exception Level

| EL | 실행 주체 | 리호스팅에서의 의미 |
|---|---|---|
| EL3 | 보안 모니터 | 부트로더가 `smc` 로 요청한다. 모델(shim)로 응답 |
| EL2 | 하이퍼바이저 | `kvm-arm.mode=protected` 면 커널 자신이 EL2 를 쓴다. 가로채면 안 된다 |
| EL1 | OS 커널 | |
| EL0 | 유저스페이스 | |

이미지를 잘못된 EL 로 진입시키면 증상이 엉뚱한 곳에서 나타난다. 그래서 이 저장소는
**계층** 개념을 둔다 → [04-loop-and-honesty.md](04-loop-and-honesty.md)

## 3. 이 저장소가 실행하는 범위

부트로더 컨테이너를 **한 번 적재**하고, 첫 스테이지부터 커널이 rootfs 를 마운트할 때까지
**하나의 연속 실행**으로 간다.

```
컨테이너 적재 → stage0 → stage1 → … → 부트로더 → 커널 → rootfs
                  ↑                        │
            리셋 PC (도출값)          부트로더가 매체에서 커널을 읽어 적재
```

| # | 단계 | 이 저장소에서 |
|---|---|---|
| ① | BootROM | 실행하지 않음. SoC 내장이라 어떤 펌웨어 패키지에도 없다. 이 단계가 **남기는 상태**만 모델링 |
| ② | 1차 부트로더 | 평문이면 **실제 실행**. 암호화되어 있으면 건너뛰고 기록 |
| ③ | 부트로더 | **실제 실행** |
| ④ | EL3 모니터 | SMC shim 으로 모델링 |
| ⑤ | EL2 하이퍼바이저 | 커널 소관. 가로채지 않음 |
| ⑥ | 커널 | **실제 실행 — 부트로더가 적재한다** |
| ⑦ | init 1단계 + 스토리지 | **실제 실행** |
| ⑧ | init 2단계 | 미해결 영역 (`/data` FBE → TEE) |
| ⑨ | Android UI | 범위 밖 (디스플레이·GPU·모뎀 모델 없음) |

### QEMU 에 커널을 직접 넘기지 않는다

`-kernel Image` · `-dtb` · `-initrd` 를 쓰지 않는다.

부트로더가 매체에서 커널을 읽고, 검증하고, DTB 를 조립해 넘긴다. 커널을 직접 넘기면 그
과정 전체를 건너뛴 것이 되어, **커널 이미지만 실행하는 것과 구별되지 않는다.**

### 실행 불가한 단계는 건너뛰고 기록한다

암호화되어 있거나 패키지에 없는 스테이지는 **다음 실행 가능한 스테이지로 진입을 재지정**한다.

건너뛰기가 정당하려면 조건이 있다: **이후 스테이지가 건너뛴 스테이지가 쓴 메모리를 읽지
않아야 한다.** 진입 코드가 무엇을 읽는지 도출해, 하드웨어 레지스터(어차피 모델링 대상)인지
이전 스테이지의 산출물인지 분류한다. 후자라면 그 값을 공급하는 것 자체가 우회이며 기록 대상이다.

**건너뛴 스테이지를 대신할 값을 지어내지 않는다.** 이후 단계가 그런 값을 필요로 한다면
그것은 채워 넣을 대상이 아니라 보고할 사실이다.

## 4. 목표 단계와 등급

목표 단계는 고정하지 않는다. 스테이지 수가 펌웨어마다 다르므로 `stage_map.json` 이 세고,
그만큼 칸이 만들어진 뒤 공통 후단이 붙는다.

```
stage_entry × N → <표면> → medium_up → partitions
                → verify_ok → kernel_entry → userspace → rootfs
```

| 등급 | 범위 | 뜻 |
|---|---|---|
| **F1** | 스테이지 진입 전부 + 표면 | 부트로더 체인이 실제로 동작 |
| **F2** | F1 + 매체·파티션·검증·커널 진입 | 부트로더가 커널을 적재·검증·기동 |
| **F3** | F2 + userspace·rootfs | rootfs 마운트까지 완주 |

**F1 은 스토리지 모델 없이 도달 가능하다.** 첫 스테이지는 이전 단계가 남긴 함수 포인터로
블록을 읽으므로, 매체 모델이 아직 없어도 진행된다. F1 을 확정한 뒤 F2 로 간다.

## 5. 무엇이 어려운가

| # | 유형 | 무슨 일이 일어나나 | 담당 |
|---|---|---|---|
| 1 | 주변장치 부재 | 없는 주소에 접근 → data abort, 또는 상태 비트를 무한 폴링 | `fixer-memory` |
| 2 | 보안 환경 부재 | `smc` → EL3 모니터 없음 → undefined instruction | `fixer-el3` |
| 3 | 이전 단계 부재 | 첫 스테이지가 이전 단계의 함수 포인터를 호출 | `fixer-bootflow` |
| 4 | 무결성 검사 | 서명 검증이 이 환경에서 실패 | `fixer-secureboot` |
| 5 | 스토리지 컨트롤러 | 벤더 드라이버가 문서 없는 레지스터를 폴링 | `fixer-storage` |
| 6 | 커널 보안 게이트 | FIPS·DEFEX·SELinux 가 panic | `fixer-kernel` |

### 기술적 실패보다 위험한 것 — 허위 통과

부팅한 것처럼 보이게 만드는 것은 쉽다.

| 수법 | 왜 허위인가 |
|---|---|
| 적응형 토글("12회 읽은 뒤 값 변경") | 펌웨어를 잘못된 분기로 보내며, 다른 펌웨어에서 재현되지 않는다 |
| 머신이 프롬프트 문자열을 출력 | 우리가 출력한 것이다 |
| 머신이 자기 수신 버퍼를 채움 | 자기 자신과 대화한 것이다 |
| 트램폴린으로 핸들러 강제 호출 | 입력 → 디스패처 경로가 성립하지 않았다 |
| 서명 검증을 패치로 무력화 | 검증을 거쳤다는 주장 자체가 성립하지 않는다 |

이 저장소의 상당 부분(출력 출처 검증 · 6항목 검증 · 정직성 규칙)은 **허위 통과를 코드로
막는 장치**다 → [04-loop-and-honesty.md](04-loop-and-honesty.md)

## 6. 왜 이 지점이 중요한가

| 도달 지점 | 가능해지는 것 |
|---|---|
| 부트로더 표면 | 명령 파서에 **입력을 넣어 시험**할 수 있다 (파서 분석의 출발점) |
| 스테이지 연속 실행 | 각 단계가 다음 단계에 무엇을 넘기는지 **관찰**할 수 있다 |
| 서명 검증 통과 | 검증 코드가 **실제로 수행**됐음을 양방향으로 증명 |
| 커널 진입 | 부트로더의 정상 부팅 결정 로직을 끝까지 추적 |
| rootfs 마운트 | 벤더 스토리지 컨트롤러 동작 사양을 복원했다는 증명 |

| # | 이유 | 구체적으로 |
|---|---|---|
| 1 | 실기기로는 불가능한 관측 | 부트로더·커널 초기화 구간은 디버거가 붙지 않는다. QEMU 는 모든 명령과 임의 시점의 메모리 전체를 준다 |
| 2 | 기기 손상 없는 반복 | 부트 파티션을 잘못 건드리면 실기기는 복구 불가가 된다 |
| 3 | 상위 권한 공격면 연구 | 부트로더는 커널보다 먼저, 더 높은 권한으로 실행된다 |
| 4 | 문서 없는 인터페이스 복원 | 데이터시트 없이 드라이버만 보고 컨트롤러 사양을 역으로 복원하는 방법 |
| 5 | 재현성 | 재현 키트로 **빌드 없이** 같은 상태를 재현한다 |
