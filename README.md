# sboot-rehost

모바일 기기 펌웨어를 QEMU 위에서 **원본 바이너리 그대로** 실행시키는 Claude Code 플러그인.

부트로더 컨테이너를 한 번 적재하고, 첫 스테이지부터 커널이 rootfs 를 마운트할 때까지
**하나의 연속 실행**으로 간다. 다음 단계 적재는 펌웨어 자신의 코드가 한다.

```
컨테이너 적재 → stage0 → stage1 → … → 부트로더 → 커널 → rootfs
                  ↑                        │
            리셋 PC (도출값)          부트로더가 매체에서 커널을 읽어 적재
```

`-kernel Image` · `-dtb` · `-initrd` 를 QEMU 에 주지 않는다. 커널을 떠먹이면 커널
이미지만 실행하는 방식과 구별되지 않는다.

---

## 설치와 사용

```
/plugin marketplace add hyu-sslab/sboot-rehost
/plugin install sboot-rehost@sboot-rehost-marketplace
```

```
/sboot-rehost:init                  설치 후 1회. 옛 캐시 삭제 + QEMU 빌드 (약 18분)
_inbox/ 에 펌웨어 배치
/sboot-rehost:start [F1|F2|F3]      인식부터 검증까지 자율 진행
/sboot-rehost:status                진행 확인
/sboot-rehost:export                재현 키트
```

| 등급 | 도달 목표 |
|---|---|
| **F1** | 부트로더 체인 동작. 스토리지 모델 없이 도달 가능 |
| **F2** | 커널이 **실제로 실행** (`Linux version` 출력) |
| **F3** | rootfs 마운트까지 완주 |

`kernel_entry`(부트로더가 `Starting kernel...` 출력)와 `kernel_alive`(커널이 자기 배너
출력)를 구분한다. 앞의 것만으로 도달을 세면 커널이 실행되지 않은 실행을 완주로 보고하게
된다.

## 검증

판정을 막는 것은 셋뿐이다. 목적은 **머신이나 에이전트가 만들어 낸 콘솔이 진짜 부팅으로
읽히지 않게 하는 것**.

| # | 게이트 | 통과 조건 |
|---|---|---|
| 1 | 소스 대조 | 머신 소스가 출력하는 문자열이 콘솔에 없다 |
| 2 | 출력 출처 | 콘솔의 고정 문자열이 펌웨어 이미지 안에 있다 |
| 3 | 입력 출처 | 머신이 자기 수신 버퍼를 채우지 않는다 |

셋 다 통과하면 `VERIFIED`, 하나라도 실패하면 `UNVERIFIED`.
**`VERIFIED` 는 콘솔의 출처가 확인됐다는 뜻이지 부팅 완주가 아니다.**

체인 트레이스 · 검증 양방향 · 스토리지 이중 구동 · 우회 기록은 측정해서 보고만 한다.

### 지키는 것

- 추측 스텁 금지. 특히 적응형 토글은 다른 펌웨어에서 재현되지 않는다
- 우회는 우회로 표기 (대상 · 이유 · 방법 · 부작용)
- 도달하지 못한 지점은 그렇게 기록
- 검증 결과 자체는 위조하지 않는다

## 정지

**회차 수와 소요 시간은 정지 사유가 아니다.**

| 코드 | 뜻 |
|---|---|
| `BLOCKED_VERSION` | 로드된 플러그인이 최신이 아님 |
| `BLOCKED_ENV` | 실행 환경 미비 |
| `BLOCKED_ARCH` | 그 아키텍처의 진입 스텁 시그니처 미정의 |
| `BLOCKED_CARVE` | 컨테이너가 부분 추출 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로 없음 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산 없음 |
| `BLOCKED_KO` | `.ko` 부재이고 커널 빌트인도 아님 |
| `BLOCKED_BUILD` | 재빌드 실패 |
| `BLOCKED_TEE` | 시큐어 월드. 설계상 범위 밖 |
| `EXHAUSTED` | 시도 소진 |

정지하면 `RESUME.md` 가 자동 생성된다. 도달 지점, 마지막 지문, 시도한 변경과 그 효과,
아직 안 써본 수단, 재개 명령이 들어간다. **정지는 인계이며 재개 가능하다.**

## 현재 상태

| 항목 | 상태 |
|---|---|
| 결정론 계층 (스크립트 · 검문 · 기록) | 동작. 시험 196개 |
| 파이프라인 배선 | 스텁 하네스로 완주 확인 |
| 실제 QEMU 실행 | **없음** |
| `machine_full.c.tmpl` | **컴파일한 적 없음.** placeholder 35개 |
| `build_lu.py` 의 GPT | 재파싱으로만 확인 |
| 서명 검증 통과 | 사례 없음 |

Exynos 계열 대상. AArch32 부트로더(MediaTek LK 등)는 진입 스텁 시그니처와 머신 템플릿이
없어 `BLOCKED_ARCH` 로 정지한다.

새 SoC 는 `profiles/` 에 탐색 힌트 파일 하나를 추가하는 것으로 시작한다. **값이 아니라
어디를 볼지만 적는다.**
