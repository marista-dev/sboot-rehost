# sboot-rehost

모바일 기기의 펌웨어를 QEMU 위에서 **원본 바이너리 그대로** 실행시키는 Claude Code
플러그인입니다.

부트로더 컨테이너를 한 번만 적재하고, 첫 스테이지부터 커널이 rootfs 를 마운트할 때까지
**하나의 연속 실행**으로 진행합니다. 다음 단계를 메모리에 올리는 일은 펌웨어 자신의
코드가 수행합니다.

```
컨테이너 적재 → stage0 → stage1 → … → 부트로더 → 커널 → rootfs
                  ↑                        │
            리셋 PC (도출한 값)        부트로더가 매체에서 커널을 읽어 적재
```

**QEMU 에 `-kernel Image` 와 `-dtb`, `-initrd` 를 넘기지 않습니다.** 커널을 직접 넘기면
부트 과정을 건너뛴 것이 되어, 커널 이미지만 실행하는 방식과 구별되지 않기 때문입니다.

---

## 설치

```
/plugin marketplace add hyu-sslab/sboot-rehost
/plugin install sboot-rehost@sboot-rehost-marketplace
```

## 사용

```
/sboot-rehost:init                  설치 후 1회. 옛 캐시를 지우고 QEMU 를 빌드합니다
_inbox/ 에 펌웨어를 넣습니다
/sboot-rehost:start [F1|F2|F3]      인식부터 검증까지 자율로 진행합니다
/sboot-rehost:status                진행 상태를 확인합니다
/sboot-rehost:export                완료 후 재현 키트를 만듭니다
```

명령은 이 넷뿐입니다. `init` 이 따로 있는 이유는 QEMU 빌드에 약 18분이 걸리기
때문입니다. 이 작업을 실행 명령 안에 넣으면 리호스팅이 시작된 줄 아는 사용자를 그만큼
기다리게 만듭니다. 환경은 펌웨어가 몇 개이든 한 번만 만들면 됩니다.

### 목표 등급

목표 단계의 개수는 펌웨어마다 다르므로 고정하지 않습니다. `stage_map.json` 이 실행
가능한 스테이지를 세고, 그 개수만큼 앞부분이 만들어진 뒤에 공통 뒷부분이 붙습니다.

| 등급 | 도달 목표 |
|---|---|
| **F1** | 부트로더 체인이 실제로 동작합니다. 스토리지 모델이 없어도 도달할 수 있습니다 |
| **F2** | 부트로더가 커널을 적재하고 검증한 뒤, **커널이 실제로 실행됩니다** |
| **F3** | rootfs 마운트까지 완주합니다 |

F2 에서 한 가지를 구분합니다. 부트로더가 `Starting kernel...` 을 출력한 것과 커널이
자기 배너인 `Linux version` 을 출력한 것은 다릅니다. 앞의 것만으로 도달했다고 세면,
커널이 실행되지 않은 실행을 완주로 보고하게 됩니다.

## 다른 접근과 무엇이 다른가

| 항목 | 흔한 접근 | 이 플러그인 |
|---|---|---|
| 커널 적재 | QEMU 가 직접 올립니다 | **부트로더가 매체에서 읽어 올립니다** |
| 부트 단계 | 건너뜁니다 | 평문인 스테이지는 실제로 실행합니다 |
| 서명 검증 | 패치로 무력화합니다 | **무력화하지 않는 것을 설계 원칙으로 둡니다** |
| 실행 불가 구간 | 언급하지 않습니다 | 건너뛰고 **그 사실과 부작용을 기록합니다** |
| 성공 판정 | 콘솔에 문자열이 보이면 성공으로 봅니다 | 콘솔이 펌웨어에서 나왔는지를 바이트로 대조합니다 |

서명 검증에 관해서는 정확히 적어 둡니다. 이 플러그인은 검증 루틴을 NOP 으로 만드는
방식을 금지하고, 상태 워드만 바꾸는 우회는 기록을 남기는 조건으로 허용합니다. 다만
**어떤 펌웨어에서도 아직 서명 검증을 통과시킨 사례는 없습니다.** 이것은 지향하는
목표이지 이미 달성한 결과가 아닙니다.

## 정직성

리호스팅에서 가장 흔한 실패는 기술적 실패가 아니라 **허위 통과**입니다. 부팅한 것처럼
보이게 만드는 일이 실제로 부팅시키는 일보다 훨씬 쉽기 때문입니다.

| 수법 | 왜 허위인가 |
|---|---|
| 적응형 응답 (예: "12회 읽은 뒤에 값을 바꾼다") | 펌웨어를 잘못된 분기로 보내며, 다른 펌웨어에서 재현되지 않습니다 |
| 머신이 프롬프트 문자열을 직접 출력 | 펌웨어가 아니라 우리가 출력한 것입니다 |
| 머신이 자기 수신 버퍼를 채움 | 펌웨어가 자기 자신과 대화한 것입니다 |
| 서명 검증을 패치로 무력화 | 검증을 거쳤다는 주장 자체가 성립하지 않습니다 |

이 저장소의 상당 부분은 위 수법들을 **코드로 막는 장치**입니다.

- **출력 출처 검증**: 콘솔에 나온 문자열이 머신 소스에도 있으면 그 도달을 무효로
  처리합니다. 매 회차 자동으로 수행합니다.
- **변경 1건 검문**: diff 로 한 회차에 들어간 변경의 개수를 강제합니다.
- **정지 판정 우선**: 관측으로 확정된 정지를 에이전트가 뒤집으면 파이프라인이 강제로
  멈추고 그 모순을 기록합니다.

### 검증

판정을 막는 항목은 셋뿐입니다. 목적은 하나입니다. **머신이나 에이전트가 만들어 낸
콘솔이 진짜 부팅으로 읽히지 않게 하는 것**입니다.

| # | 게이트 | 통과 조건 |
|---|---|---|
| 1 | 소스 대조 | 머신 소스가 출력하는 문자열이 콘솔에 나타나지 않습니다 |
| 2 | 출력 출처 | 콘솔의 **고정 문자열**이 펌웨어 이미지 안에 존재합니다 |
| 3 | 입력 출처 | 머신이 자기 수신 버퍼를 채우지 않습니다 |

판정 결과는 **`VERIFIED`(출처 검증 통과)** 또는 **`UNVERIFIED`(출처 검증 실패)** 입니다.
`VERIFIED` 는 콘솔이 펌웨어에서 나왔다는 뜻이며, **부팅을 완주했다는 뜻이 아닙니다.**
어디까지 도달했는지는 마일스톤으로 따로 확인합니다.

다음 넷은 측정해서 보고만 하고 판정을 막지 않습니다. 이들까지 모두 통과 조건으로 두면
실제로 이룬 진전이 실패 판정 하나에 묻히기 때문입니다.

- 체인 실행 트레이스: 스테이지 진입 주소가 순서대로 나타나는가
- 검증 양방향: 정상 이미지는 통과하고 1바이트를 훼손한 이미지는 실패하는가
- 스토리지 이중 구동: 같은 컨트롤러 모델을 부트로더 드라이버와 커널 드라이버가 모두
  구동하는가
- 우회 기록: 모든 우회가 대상, 이유, 방법, 부작용 네 항목을 갖추었는가

게이트를 완화한 뒤에도 다음 넷은 그대로 지킵니다. 추측으로 만든 스텁을 넣지 않고,
우회는 우회라고 표기하며, 도달하지 못한 지점은 그렇게 기록하고, 검증 결과 자체는
위조하지 않습니다.

## 정지

**회차 수와 소요 시간은 정지 사유가 아닙니다.** 시도할 수단이 남아 있는 한 계속합니다.

| 코드 | 뜻 |
|---|---|
| `BLOCKED_VERSION` | 세션이 로드한 플러그인이 최신이 아닙니다 |
| `BLOCKED_ENV` | 실행 환경이 준비되지 않았습니다 |
| `BLOCKED_ARCH` | 그 아키텍처의 진입 스텁 시그니처가 아직 정의되지 않았습니다 |
| `BLOCKED_CARVE` | 컨테이너가 일부만 추출되었습니다 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로가 없습니다 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산이 없습니다 |
| `BLOCKED_KO` | 벤더 커널 모듈이 없고 커널에 내장되지도 않았습니다 |
| `BLOCKED_BUILD` | 머신 재빌드가 실패했습니다 |
| `BLOCKED_TEE` | 시큐어 월드에 속하므로 설계상 범위 밖입니다 |
| `EXHAUSTED` | 시도할 수단이 소진되었습니다 |

정지하면 `RESUME.md` 가 자동으로 만들어집니다. 여기에는 도달 지점, 마지막 실행 지문,
시도한 변경과 각각이 지문을 움직였는지, 아직 시도하지 않은 수단, 재개 명령이 들어갑니다.
**정지는 중단이 아니라 인계이며, 같은 명령으로 이어서 진행할 수 있습니다.**

## 현재 상태

과장 없이 적습니다.

| 항목 | 상태 |
|---|---|
| 결정론 계층 (스크립트, 검문, 기록) | 동작하며 196개 시험으로 회귀를 막습니다 |
| 파이프라인 배선 | 스텁 하네스로 끝까지 완주하는 것을 확인했습니다 |
| 실제 QEMU 실행 | **이 저장소에서는 아직 수행하지 않았습니다** |
| `machine_full.c.tmpl` | **컴파일한 적이 없습니다.** 35개 placeholder 를 먼저 채워야 합니다 |
| `build_lu.py` 가 만드는 GPT | 재파싱으로만 확인했고, 실제 UFS 드라이버가 읽은 적은 없습니다 |
| 서명 검증 통과 | 사례 없음 |

## 지원 대상

Samsung Exynos 계열을 대상으로 개발했습니다. `profiles/` 에 MediaTek 힌트 파일이
있지만, MediaTek LK 를 비롯한 AArch32 부트로더는 진입 스텁 시그니처와 머신 템플릿이
아직 없어서 `BLOCKED_ARCH` 로 정지합니다.

새 SoC 를 지원하려면 `profiles/` 에 탐색 힌트 파일을 하나 추가하는 것에서 시작합니다.
이 파일에는 **어디를 볼지만 적고 주소나 오프셋 같은 값은 넣지 않습니다.** 값은
static-analyzer 가 대상 펌웨어에서 도출합니다.
