# sboot-rehost

모바일 기기 펌웨어를 QEMU 위에서 **원본 바이너리 그대로** 실행시키는 Claude Code 플러그인이다.

부트로더 컨테이너를 한 번 적재하고, 첫 스테이지부터 커널이 rootfs 를 마운트할 때까지
**하나의 연속 실행**으로 간다. 다음 단계 적재는 펌웨어 자신의 코드가 수행한다.

```
컨테이너 적재 → stage0 → stage1 → … → 부트로더 → 커널 → rootfs
                  ↑                        │
            리셋 PC (도출값)          부트로더가 매체에서 커널을 읽어 적재
```

**QEMU 에 `-kernel Image` · `-dtb` · `-initrd` 를 주지 않는다.** 커널을 직접 넘기면 부트
과정을 건너뛴 것이 되어, 커널 이미지만 실행하는 것과 구별되지 않는다.

---

## 설치

```
/plugin marketplace add hyu-sslab/sboot-rehost
/plugin install sboot-rehost@sboot-rehost-marketplace
```

## 사용

```
_inbox/ 에 펌웨어 배치
/sboot-rehost:start [F1|F2|F3]      환경 준비부터 검증까지 자율 진행
/sboot-rehost:status          진행 확인
/sboot-rehost:export          완료 후 재현 키트
```

| 등급 | 범위 |
|---|---|
| **F1** | 부트로더 체인이 실제로 동작 (스토리지 모델 없이 도달 가능) |
| **F2** | 부트로더가 커널을 적재·검증·기동 |
| **F3** | rootfs 마운트까지 완주 |

---

## 무엇이 다른가

| | 일반적인 접근 | 이 저장소 |
|---|---|---|
| 커널 | QEMU 가 직접 적재 | **부트로더가 매체에서 읽어 적재** |
| 부트 단계 | 건너뜀 | 평문인 스테이지는 실제 실행 |
| 서명 검증 | 무력화 | **통과시킨다.** 무력화하면 주장 자체가 성립하지 않는다 |
| 실행 불가 구간 | 언급 없음 | 건너뛰고 **그 사실을 기록** |
| 성공 판정 | 콘솔 문자열 | 실행 증거 6항목 전부 |

## 정직성

리호스팅에서 가장 흔한 실패는 기술적 실패가 아니라 **허위 통과**다. 부팅한 것처럼 보이게
만드는 것은 쉽기 때문이다.

| 수법 | 왜 허위인가 |
|---|---|
| 적응형 응답("12회 읽은 뒤 값 변경") | 펌웨어를 잘못된 분기로 보내며 재현되지 않는다 |
| 머신이 프롬프트 문자열을 출력 | 우리가 출력한 것이다 |
| 머신이 자기 수신 버퍼를 채움 | 자기 자신과 대화한 것이다 |
| 서명 검증을 패치로 무력화 | 검증을 거쳤다는 주장이 성립하지 않는다 |

이 저장소의 상당 부분은 이를 **코드로 막는 장치**다.

- **출력 출처 검증** — 콘솔 문자열이 머신 소스에도 있으면 해당 도달을 무효화 (매 회차 자동)
- **변경 1건 검문** — diff 로 회차당 변경 수를 강제
- **정지 판정 우선** — 에이전트가 정지를 뒤집으면 강제 정지 + 모순 기록
- **출처 검증 게이트 3항** — 머신·에이전트가 지어낸 콘솔을 막는다. 통과해도 부팅 완주를 뜻하지 않는다

### 검증 6항목

| # | 항목 |
|---|---|
| 1 | 체인 실행 트레이스 (스테이지 진입 PC 가 순서대로 + 커널 진입) |
| 2 | 출력 바이트 대조 (콘솔 토큰이 펌웨어 안에 존재) |
| 3 | 소스 반증 (머신 소스에 동일 문자열 0개) |
| 4 | **검증 양방향** (정상 통과 + 1바이트 훼손 시 실패) |
| 5 | **스토리지 이중 구동** (부트로더 드라이버와 커널 드라이버 둘 다) |
| 6 | 우회 기록 (대상·이유·방법·부작용) |

항목 4 와 5 는 "통과했다"만으로는 증명되지 않는 것을 증명한다.
항상 통과하는 검증기는 항상 통과하는 스텁과 구별되지 않고, 한 드라이버에 맞춘 스토리지
모델은 컨트롤러의 모델이 아니라 그 드라이버 기대치의 모델이다.

## 정지

**회차 수와 소요 시간은 정지 사유가 아니다.** 시도할 수단이 남아 있는 한 계속한다.

| 코드 | 뜻 |
|---|---|
| `BLOCKED_VERSION` | 세션이 로드한 플러그인이 최신이 아님 |
| `BLOCKED_ENV` | 실행 환경 미비 |
| `BLOCKED_ARCH` | 해당 아키텍처의 진입 스텁 시그니처 미정의 |
| `BLOCKED_CARVE` | 컨테이너가 부분 추출 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로 없음 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산 없음 |
| `BLOCKED_TEE` | 시큐어월드 — 설계상 범위 밖 |
| `EXHAUSTED` | 시도 소진 |

정지 시 `RESUME.md` 가 자동 생성된다: 도달 지점, 마지막 지문, 시도한 변경과 각각의 효과,
아직 시도하지 않은 수단, 재개 명령. **정지는 중단이 아니라 인계다.**

## 지원 대상

Samsung Exynos · MediaTek 계열에서 검증 중이다. 새 SoC 지원은 `profiles/` 에 탐색 힌트
파일 하나를 추가하는 것으로 시작한다 — 주소나 오프셋 같은 **값은 넣지 않는다.**

AArch32 부트로더(MediaTek LK 등)는 진입 스텁 시그니처와 머신 템플릿이 아직 없어
`BLOCKED_ARCH` 로 정지한다.
