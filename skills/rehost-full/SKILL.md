당신은 **통합 체인 리호스팅** 오케스트레이터.
`/sboot-rehost:rehost-full` 호출 시 **`workflows/pipeline.js` 를 호출**한다. 트랙 인자는 없다.

## 한 문장

> **한 머신, 한 진입점, 나머지는 게스트 안에서.**

QEMU 는 부트로더 컨테이너만 올리고 리셋 PC 를 **첫 실행 가능 스테이지**에 둔다.
그다음 스테이지도, 커널도, DTB 도 **펌웨어 자신의 코드가** 매체에서 읽어 적재한다.

```
[컨테이너 한 번 적재]
   stage0 ──▶ stage1 ──▶ … ──▶ 부트로더 ──▶ 커널 ──▶ rootfs
     ▲          ▲                  │
     │          └ 암호화 스테이지는 건너뛰고 다음 실행 가능 스테이지로 재지정
     └ 리셋 PC (도출값)
```

### 하지 않는 것

| | 이유 |
|---|---|
| `-kernel Image` · `-dtb` · `-initrd` | 부트로더가 매체에서 직접 읽고 DTB 를 조립한다. 떠먹이면 **커널만 올린 기존 연구와 같아진다** |
| 이미지 carve | 머신 init 이 컨테이너 하나를 열어 스테이지별 VA 로 `memcpy` |
| 트램폴린 · entry redirect | 진입 스텁이 자기완결이므로 필요 없다 |

## 인자

```
pipeline.js({
  workdir, model, target: 'F1'|'F2'|'F3',
  bootloader_path,          // 부트로더 컨테이너 (구 bl3_path 도 허용)
  soc_family, arch, bl_surface, has_super,
  invoked_with,             // 사용자 입력 원문 — 요약하지 말고 그대로
  plugin_dir: '${CLAUDE_PLUGIN_ROOT}',
})
```

**`invoked_with` 는 반드시 넘긴다.** 사용자가 실제로 친 말이 `prompts.jsonl` 과 `JOURNAL.md`
에 원문으로 남고, 실행이 멈췄을 때 *왜 이 방향이었는지*를 되짚는 유일한 근거가 된다.
넘기지 않으면 파이프라인이 "지시 맥락이 기록되지 않았다"고 저널에 남긴다.

## 등급 — 목표 단계는 도출값이다

스테이지 수는 펌웨어마다 다르므로 **고정하지 않는다.** `stage_map.json` 이 실행 가능
스테이지를 세고, 그만큼 칸이 생긴 뒤 공통 후단이 붙는다.

| 등급 | 목표 단계 | 뜻 |
|---|---|---|
| **F1** | 스테이지 진입 × N + `<표면>` | 부트로더 체인이 진짜로 돈다 |
| **F2** | F1 + `medium_up` · `partitions` · `verify_ok` · `kernel_entry` | **정식 커널 부팅** |
| **F3** | F2 + `userspace` · `partitions_up` (+ `super_mounted`) | 완주 |

`super.img` 가 없는 펌웨어(raw system/vendor)는 `super_mounted` 를 목표 단계에 넣지 않는다.

**F1 은 매체 모델 없이 도달 가능하다.** 첫 스테이지는 핸드오프 슬롯으로 블록을 읽으므로
UFS/eMMC 모델이 아직 없어도 걸어간다. **F1 을 먼저 확정하고 F2 로 간다.**

## 시작 전에 파이프라인이 스스로 막는 것

| 코드 | 조건 |
|---|---|
| **`BLOCKED_VERSION`** | 세션이 로드한 플러그인이 최신이 아님 — **갱신·재시작 안내 후 정지.** 옛 버전으로 돌면 회차·로그·판정이 모두 옛 규칙을 따른다 |
| `BLOCKED_ENV` | 실행 환경 미비 (WSL/QEMU/ninja/capstone) |
| `BLOCKED_ARCH` | 그 아키텍처의 진입 스텁 시그니처가 아직 없음 (현재 arm32). **"스테이지 없음"이 아니라 도구의 결손** |
| `BLOCKED_CARVE` | 컨테이너가 부분 추출 |
| `BLOCKED_NO_INPUT_PATH` | 어느 표면에도 입력 경로가 없음 |
| `BLOCKED_ASSET` | F2 이상인데 커널 자산 없음 (F1 로 낮추면 진행 가능) |
| `BLOCKED_TEE` | 시큐어월드 — 설계상 범위 밖 |
| `EXHAUSTED` | 시도 소진 (회차 수는 정지 사유가 아니다) |

정지하면 **`RESUME.md`** 가 자동 생성된다 — 어디까지 갔나, 무엇을 시도했고 각각이 지문을
움직였나, 아직 안 써본 수단, 재개 명령. 정지는 포기가 아니라 인계다.

## 검증 — 6/6

| # | 항목 |
|---|---|
| 1 | **체인 PC 트레이스** — 스테이지 진입 PC 가 순서대로 등장 + 커널 진입 |
| 2 | 출력 byte-match — 콘솔 토큰이 펌웨어 안에 file offset 으로 존재 |
| 3 | 소스 negative — 머신 C 에 그 문자열 0 개 |
| 4 | **검증 양방향** — 정상 vbmeta 통과 **AND** 1바이트 훼손 시 실패 |
| 5 | **스토리지 이중 구동** — 부트로더 드라이버와 커널 드라이버 **둘 다** 파티션 열거 |
| 6 | 우회 기록 — 대상·이유·방법·부작용 |

**6/6 만 REAL. 5/6 이하는 FORCED.** 부분 점수 없음.

> 항목 4 를 통과만으로 채우지 마라. **항상 통과하는 검증기는 항상 통과하는 스텁과 구별되지
> 않는다.** 훼손 이미지가 실패해야 비로소 검증이 실제로 돌았다는 증거가 된다.

## 구 명령과의 관계

`rehost-bootloader`(트랙 1) 와 `rehost-kernel`(트랙 2) 을 **대체**한다. 두 트랙은 부트로더에
스토리지 모델이 없고 커널에 부트로더가 없어서 갈라져 있었는데, 통합 플로우는 같은 이미지
안에서 둘 다 하므로 가를 이유가 없다.

**같은 스토리지 모델을 부트로더 드라이버와 커널 드라이버가 차례로 구동한다.** 한쪽에 맞춘
가짜 모델은 다른 쪽에서 깨지므로, 이 구조 자체가 검증 장치다.
